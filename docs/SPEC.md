## 1. 目標

在 iPhone、iPad 和桌面瀏覽器上，用一個 iOS「加入主畫面」的 Web App：

1. 看**持倉**和**關注**股票的即時走勢與 K 線；
2. 看**大盤**（加權指數、櫃買指數）的走勢與 K 線；
3. 設定**警報**，條件成立時用 **iOS 推播**通知（Telegram 當備援）。

這是**看盤工具**，不是下單工具，也不是記帳工具。

## 4. 範圍

**包含（v1）**

- 總覽：大盤、持倉摘要、持倉清單、自選清單。
- 個股頁與指數頁：分時線、日／週／月 K、均線、成交量、副圖（KD、MACD、RSI）、十字游標、縮放平移。
- 圖表疊加：我的平均成本線、警報價位線；買賣點標記。
- 自選清單：多份清單、搜尋新增、排序、刪除。
- 警報：6 種規則、3 種頻率、通知紀錄。
- iOS Web App：安裝、推播、離線唯讀、深層連結、安全區域。
- 設定：通知、顏色慣例、主題、圖表預設、資料來源狀態。

**不包含（v1）**

- 下單、帳戶餘額、委託與成交回報。
- 五檔報價、逐筆明細、籌碼（法人、融資券）、財報、新聞、個股研究筆記。
- 台指期、美股、加密貨幣。
- 過去的分鐘 K、多日分時線。
- 在 App 內新增或修改成交（資料由後端匯入）。
- 自訂指標、畫線工具、多圖表同步。
- 多使用者。

## 5. 使用情境

1. **開盤前**：打開 App，確認大盤狀態、持倉昨天的損益、有沒有未讀警報。
2. **盤中**：看持倉今日損益；點進個股看分時線，確認有沒有跌破成本線；長按圖表在某個價位設警報，然後鎖屏。
3. **被通知**：鎖屏收到推播「示範半導體 到價 ≥ 100」，點開直接進入該股，看到現價和圖表。
4. **盤後**：看日 K 與均線，決定明天要不要加警報；清理已觸發的警報。
5. **查個股**：搜尋代號或名稱，看走勢，加入自選。

### 6.5 警報

#### 規則

| 類型 | 說明 | 範例 |
|---|---|---|
| `price` | 成交價 ≥ 或 ≤ 某價 | 示範半導體 ≥ 100 |
| `change_pct` | 今日漲跌幅（相對昨收）≥ 或 ≤ 某百分比 | ≤ −5% |
| `pnl_pct` | 持倉未實現損益％ ≥ 或 ≤ 某值（只有持有時） | ≥ +20% |
| `volume_ratio` | 今日累計量 ≥ N 倍近 5 日平均量 | ≥ 2 倍 |
| `ma_cross` | 現價上穿或下穿日 K 的 5／10／20／60 日均線 | 下穿 20 日線 |
| `limit` | 成交價到達漲停或跌停 | 漲停 |

#### 語意

| ID | 規則 |
|---|---|
| A-1 | **邊緣觸發**：條件從「不成立」變成「成立」才通知，不是一直成立就一直通知。 |
| A-2 | 建立時如果條件**已經成立**，不會立刻通知；介面要明講（「目前已滿足條件，需先離開條件，再次觸及時才會通知」）。 |
| A-3 | **頻率**：`once`＝通知後自動停用（狀態變成「已觸發」）；`daily`＝每個交易日最多一次；`every`＝條件離開後再次成立就通知，兩次通知至少間隔 `cooldown_minutes`（預設 30，最小 5）。 |
| A-4 | **只在有效資料上判斷**：報價狀態是 `live` 或 `delayed` 才判斷；`stale`、`disconnected` 不判斷也不誤報。資料恢復後，若條件已成立且尚未通知，補發並標示「延後補發」（`late=true`）。 |
| A-5 | **判斷時段**：盤中（含收盤撮合）。盤前、盤後、休市不判斷。 |
| A-6 | 同一次條件成立只通知一次（不論重試或多個裝置）；重複請求不會產生重複通知。 |
| A-7 | 警報可設到期時間，到期自動變成 `expired`。 |
| A-8 | 持倉清空時，`pnl_pct` 警報自動變成 `error`，並說明原因。 |
| A-9 | 上限：總共 100 則，每個商品 10 則。 |

#### 通知內容

- 標題：`{名稱} {代號}｜{規則說明}`，例如「示範半導體 TS01｜價格 ≥ 100.00」。
- 內文：`現價 {價格}（{±漲跌％}）· {HH:mm} · {資料狀態}`。延後補發要註明。
- 點擊通知：開啟該商品個股頁，並標示觸發的警報。
- 同一個警報的新通知取代前一則（不洗版）。

#### 通知管道

- 推播（預設）與 Telegram 都可以在警報上個別選擇。
- 偏好設定：「推播失敗或沒有可用裝置時改送 Telegram」預設開；「所有警報同時送 Telegram」預設關。
- Telegram 的連線由後端／囉哈設定，App 只顯示「已連線／未連線」。

### 6.6 通知紀錄（`/stocks/inbox`）

- 時間倒序列出已觸發的通知：商品、規則、觸發當下的價格、各管道的投遞結果（成功／失敗／略過）。
- 未讀標記、全部標為已讀；點擊進入該商品。

## 7. 資料定義與計算

| 名詞 | 定義 |
|---|---|
| 漲跌、漲跌％ | `change = last − prev_close`；`change_pct = change ÷ prev_close × 100`。`direction` 由伺服器依這個值給出（`flat` 表示相等）。 |
| 漲停、跌停 | 昨收的 ±10%，依升降單位取整。價格被限制時 `limit_state` 為 `limit_up` 或 `limit_down`。 |
| 市場時段 | 盤前 08:30–09:00（`pre_open`）；盤中 09:00–13:25（`open`）；收盤撮合 13:25–13:30（`closing_auction`）；盤後 13:30–14:30（`post`，價格不再變動）；其餘為休市。**實際時間與休市日以交易所公告為準，由後端提供，前端不硬編。** |
| 資料狀態 | 見 `FRONTEND-CONTRACT.md` 的 `QuoteStatus`。盤中來源時間距今 ≤ 15 秒為 `live`，15–60 秒為 `delayed`，超過 60 秒為 `stale`；已收盤的最後一筆是 `closed`，不算過期。 |
| 週 K、月 K | 由日 K 合成：週以**週一**為起始，月以 1 日為起始；開＝期間首日開盤、收＝期間最後一日收盤、高低＝期間極值、量＝加總。 |
| 還原權息 | 向前還原（以最近價格為基準）。預設不還原，與券商 App 的 K 線一致。 |
| 平均成本 | **總平均法**：`avg_cost = 持有部位的總成本 ÷ 持有股數`；買進成本含手續費；賣出時按比例減少成本。 |
| 未實現損益 | `市值 − 成本`；另提供「預估淨值」＝再扣預估賣出手續費與證交稅（股票 0.3%、ETF 0.1%）。 |
| 今日損益 | 前一個交易日收盤前就持有的股數：`(現價 − 昨收) × 股數`；今天買進的股數：`(現價 − 買進價) × 股數`。今天賣出的部分屬於已實現損益，不計入今日損益。 |
| 已實現損益（今年） | 賣出淨額減去賣出部位的平均成本；後端算得出才提供，否則顯示「—」。 |
| 成交量單位 | 張。1 張 = 1000 股。零股不計入張數。 |

## 8. 非功能需求

| 項目 | 需求 |
|---|---|
| 效能 | 總覽首次載入（有快取時）< 1 秒出畫面；圖表平移縮放 60 fps；600 根日 K 加兩個指標不卡頓。 |
| 資料新鮮度 | 盤中可見畫面的報價每 5 秒更新；背景不輪詢。 |
| 離線 | 唯讀，顯示最後資料與時間；寫入停用。 |
| iOS Web App | 獨立 App；沒有網址列與返回鍵；安全區域；下拉更新；輸入框字級 ≥ 16px（避免縮放）；點擊目標 ≥ 44pt；圖示、啟動畫面；橫向支援。 |
| 無障礙 | 漲跌不只靠顏色；圖表要有文字替代（目前價、漲跌、區間高低）；對比度達標；可調整字級。 |
| 隱私 | 公開 repo 不得包含真實持倉、成本、損益、真實股價歷史；mock 用虛構商品。 |
| 安全 | 登入由 Cloudflare Access；API 不接受未登入請求；推播只含必要資訊（不含部位數量與金額）。 |

## 10. 風險與限制（誠實版）

| 項目 | 說明 |
|---|---|
| 分鐘 K 歷史 | 沒有來源，已決定不做。分時線只能從伺服器開始累積的時間往後；新加入的商品、伺服器重啟都會有缺口，介面會明說。 |
| K 線深度 | 日 K 受 KGI 的滾動範圍限制（約 4 年）；更早的資料需要另外找來源，不在 v1。 |
