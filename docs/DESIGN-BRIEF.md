# 看盤 App — 設計需求 DESIGN-BRIEF v1.0

> 給設計者（人或 agent）。**只講介面、內容與互動**；沒有後端、資料庫、API。
> 功能細節見 `SPEC.md`，欄位與規則見 `FRONTEND-CONTRACT.md`（設計者不需要讀 API 的部分）。
> 顏色與品牌**交給設計者決定**，但有一條硬規則：**意義不能只靠顏色表達**（漲跌一定要有 ▲▼ 或 ＋－，狀態一定要有文字或圖示）。
> 本文件的所有範例數字都是**虛構**的，請不要把它們當成真實行情。

---

## 1. 需求

設計一個**看盤 App**：用 iPhone、iPad 和桌面瀏覽器，看自己的持倉與關注股票的走勢與 K 線、看大盤，並設定警報由 iOS 推播通知。

**這個 App 不下單。** 它是看盤與提醒工具。

### 1.1 平台與尺寸

| 裝置 | 尺寸 | 備註 |
|---|---|---|
| iPhone | 390×844（直式）；橫式只用於圖表全螢幕 | **主要使用情境**，單手操作 |
| iPad | 橫式 1366×1024、直式 820×1180 | 多欄；iPad 橫式是看盤的好位置 |
| 桌面 | 1440×900 | 與 iPad 橫式同一套多欄版面 |

- 介面語言：**繁體中文**。
- 執行環境：iOS「加入主畫面」的 Web App（standalone）。**沒有瀏覽器網址列，沒有系統返回鍵**（見 §8）。
- 同時提供**深色**與**淺色**主題；深色是主要使用情境（盤中、夜間）。

### 1.2 與記帳 App 的關係

同一個人使用的另一個 App（記帳）已有一套風格：深色為主、圓角卡片、iPad 以上左側是圖示導覽列、手機是底部分頁列。**希望看盤 App 看起來是同一個產品家族**，但它是獨立的 App，有自己的圖示。細節由設計者決定。

## 2. 使用者與情境

一位個人投資者，持有少量台股（個位數檔），另外關注十幾到幾十檔。

| 情境 | 需求 |
|---|---|
| 開盤前 | 一眼看到大盤狀態、持倉昨天的結果、有沒有警報 |
| 盤中 | 持倉今天賺賠多少；點進個股看分時線；有沒有跌破成本；在某個價位設警報然後鎖屏 |
| 被通知 | 鎖屏看到推播，點開直接進該股，看到現價與圖表 |
| 盤後 | 看日 K 與均線；整理警報 |
| 隨手查 | 搜尋代號或名稱，看走勢，加入自選 |

## 3. 設計原則

1. **數字第一**：價格、漲跌、損益是畫面的主角；用等寬或表格數字，欄位對齊，位數變化時不跳動。
2. **一眼看狀態**：這個價格是即時的、稍舊的、過期的，還是收盤價？看盤工具最危險的錯誤，是讓人把過期價格當成現價。
3. **台灣慣例**：預設**紅漲綠跌**；使用者可以切換成綠漲紅跌。無論哪一種，都要有 ▲▼／＋－。
4. **單手**：主要操作（切換週期、加警報、加自選）在大拇指範圍；點擊目標 ≥ 44pt。
5. **圖表好操作**：長按十字游標、雙指縮放、左右拖曳要順，不與頁面捲動打架。
6. **誠實呈現缺資料**：分時線可能不完整、K 線可能不夠長；介面要明講「自 HH:mm 起」「資料自 YYYY/MM/DD 起」，不可以補線掩蓋缺口。
7. **主畫面 App 的完整性**：沒有返回鍵與網址列，所以每一頁都要有 App 內返回。

## 4. 導覽

| 裝置 | 結構 |
|---|---|
| 手機 | 底部分頁列：**總覽、自選、警報、設定**；全域搜尋入口；個股頁等子頁用 App 內返回按鈕（左上）與邊緣滑動返回 |
| iPad／桌面（≥ 960px） | 左側圖示導覽列（總覽、自選、警報、設定、搜尋）；個股頁為**三欄**：左＝持倉與自選清單，中＝圖表，右＝報價、我的部位、警報 |

鈴鐺（未讀警報數）在總覽與個股頁都能看到。

## 5. 畫面清單與內容（依優先順序）

### 5.1 總覽

1. **市場狀態列**：盤前／盤中／收盤撮合／盤後／休市＋資料新鮮度；休市時顯示下次開市時間。
2. **大盤**：加權指數、櫃買指數兩張卡：指數、漲跌、漲跌％、今日分時迷你圖。
3. **持倉摘要**：總市值、今日損益、未實現損益（金額＋％）；損益基準切換（毛額／扣除預估稅費）；有幾檔沒有報價或報價過期的提示。
4. **持倉清單**：名稱、代號、現價、漲跌％、持有張數、損益、迷你走勢；可排序。
5. **自選清單**：同上但沒有損益；有多份清單時用分段控制切換。
6. 下拉更新、鈴鐺。

### 5.2 個股頁／指數頁

1. **標題區**：名稱、代號、現價（最大的字）、漲跌、漲跌％；資料狀態；漲停／跌停標示；加入自選、鈴鐺（設警報）。
2. **週期切換**：分時／日／週／月。
3. **圖表區**：
   - 分時：價格線、昨收參考線、漲跌停範圍、成交量柱。
   - K 線：蠟燭、成交量副圖、均線（5／10／20／60 可開關）、副圖可選 KD／MACD／RSI。
   - 疊加層：我的平均成本線、警報價位線（虛線＋鈴鐺）、買賣點標記；可個別開關。
   - 十字游標與數值浮層（開高低收、漲跌、量、均線值）。
   - 長按價位 → 「在此價位設警報」。
   - 資料不完整的提示、斷線缺口。
   - 手機橫向全螢幕。
4. **報價資訊**：開、高、低、昨收、漲停價、跌停價、成交量、成交金額、五日均量、52 週高低。
5. **我的部位**（有持倉時）：持有（張、股）、平均成本、市值、未實現損益、今日損益、占比、首次買進日；成交紀錄。
6. **警報**：這個商品的警報清單、新增。
- 指數頁沒有「成交張數」與「我的部位」；量能用成交金額。

### 5.3 自選清單管理

多份清單（分段或側邊）、搜尋新增（結果顯示是否已在清單／已持有）、拖曳排序、滑動刪除、清單的新增／命名／刪除。

### 5.4 警報

- **清單**：依狀態分組（啟用中／已暫停／已觸發／已到期／錯誤）。每則顯示商品、條件白話、目前值與「距離門檻 ±x%」、頻率、通知管道、最後觸發時間。啟用／暫停切換、滑動刪除。
- **新增／編輯**（手機用全頁或大型面板，桌面用面板）：
  1. 選商品（可從個股頁預填）。
  2. 選規則類型（6 種，用白話與範例說明）：到價、漲跌幅、持倉損益％、爆量、均線突破／跌破、漲停／跌停。
  3. 設門檻：價格用步進器與直接輸入；顯示現價，以及「距離現價 +2.3%」。
  4. 頻率：一次／每日一次／每次（並顯示冷卻時間）。
  5. 通知管道：推播、Telegram（可複選）。
  6. 備註、到期時間（選填）。
  7. 即時提示：「目前已滿足條件，不會立刻通知；需先離開條件再次觸及時才會通知」。
  8. 如果沒有任何可接收推播的裝置，提醒並導向通知設定。
- **通知紀錄**：時間倒序；觸發當下的價格；各管道投遞結果（成功／失敗／略過）；未讀標記；全部標為已讀。

### 5.5 設定

- 通知：權限狀態與啟用流程（見 §7 的 6 種狀態）、已登記的裝置（可移除）、傳送測試通知、Telegram 連線狀態、兩個備援開關。
- 顏色慣例（紅漲綠跌／綠漲紅跌）、主題（系統／深色／淺色）。
- 圖表預設：預設週期、均線、成交量、副圖、還原權息。
- 損益基準：毛額／扣除預估稅費。
- 資料來源狀態：各來源是否正常、最後更新時間。
- 關於：版本、「如何加入主畫面」圖解。

## 6. 必要狀態

每個畫面都要設計：

| 狀態 | 說明 |
|---|---|
| 載入中 | 骨架畫面（不是整頁轉圈） |
| 空狀態 | 沒有持倉、沒有自選、沒有警報、沒有通知；各有明確下一步 |
| 錯誤 | 可重試；行情來源中斷時保留上次資料並標示「資料過期」 |
| **價格狀態** | 即時、稍舊、過期、收盤、來源中斷、無資料——六種在列表、卡片、標題區、圖表上的樣子，**過期價格的視覺要比即時價格弱** |
| **市場狀態** | 盤前、盤中、收盤撮合、盤後、休市 |
| **特殊價格** | 漲停、跌停、平盤、暫停交易 |
| 圖表缺資料 | 分時線自 HH:mm 起、有缺口；K 線資料範圍不足 |
| 離線 | 最近資料＋「離線 · 資料更新於 HH:mm」；寫入功能停用 |
| 登入過期 | 面板說明，保留尚未送出的警報表單，提供重新登入 |
| 推播權限 | 6 種狀態（見 §7） |
| 版面壓力 | 4 位數價格、百萬張成交量、億元損益、很長的商品名稱（例如 ETF 全名） |

## 7. 通知設計

### 7.1 權限狀態與引導

| 狀態 | 畫面 |
|---|---|
| 不支援 | 說明需要 iOS／iPadOS 16.4 以上；警報仍可建立（走 Telegram） |
| 尚未加入主畫面 | **圖解「加入主畫面」三步驟**（分享 → 加入主畫面 → 從主畫面開啟） |
| 尚未允許 | 說明用途的畫面＋「開啟通知」按鈕（**必須由使用者點擊才能跳出系統權限視窗**，所以不能自動彈出） |
| 已啟用 | 顯示已登記的裝置、「傳送測試通知」 |
| 訂閱失效 | 「重新啟用通知」 |
| 已拒絕 | 引導到「設定 → 通知 → 看盤」開啟 |

### 7.2 通知本身（鎖屏）

標題一行、內文一行，要在鎖屏上一眼讀懂：

```
示範半導體 TS01｜價格 ≥ 100.00
現價 100.50（+2.55%）· 10:41 · 即時
```

```
範例金融控股 TS02｜今日跌幅 ≤ −5%
現價 23.80（−6.30%）· 11:02 · 延後補發
```

請設計：價格類、跌幅類、爆量類、均線類、漲停跌停類各一則，以及「延後補發」與「測試通知」的文案。App 圖示要能顯示未讀數。

## 8. iOS 主畫面 App 要求

- **沒有網址列、沒有返回鍵**：每個子頁都要有 App 內返回；支援邊緣滑動返回。
- **安全區域**：狀態列與動態島下方、底部手勢條都要留白，內容不可被蓋住或貼到邊。
- 下拉更新；更新中有明確指示；圖表區域內的拖曳**不可觸發**下拉更新。
- 輸入框字級 ≥ 16px，避免 iOS 自動縮放。
- 橫向：圖表全螢幕；其他頁面可鎖直向。
- 離線與「有新版本，重新開啟套用」的提示。
- App 圖示（含深色版）與啟動畫面。

| 元件 | 變體 |

### 圖表一覽

| 圖表 | 用途 | 互動 |
|---|---|---|
| 分時線 | 看今天的走勢與相對昨收 | 十字游標；缺口斷線；長按價位設警報 |
| K 線＋量＋均線 | 看日／週／月走勢 | 十字游標；縮放；平移；往左到底自動載入更早資料；雙擊還原 |
| 副圖 KD／MACD／RSI | 輔助判斷 | 與主圖同步十字游標 |
| 迷你走勢圖 | 列表上快速看方向 | 無（純顯示） |

| TS04 | 樣本航運 | 上市個股 | 55.00 | 漲停 |
| TS05 | 假想生技 | 上櫃個股 | 18.20 | 跌停 |
| TE01 | 示範市值 ETF | ETF | 150.00 | ▲ 0.50（+0.33%） |

## 11. 不在範圍

下單、帳戶餘額、五檔報價、逐筆明細、籌碼、財報、新聞、研究筆記、台指期、美股、加密貨幣、過去的分鐘 K、畫線工具、自訂指標、多使用者、深度客製化主題。

## 12. 交付項目

1. 設計系統：色彩（深色＋淺色）、字型與數字樣式、間距、圓角、圖示、圖表樣式。
2. 每一個畫面（§5）在 **iPhone、iPad 橫式、iPad 直式、桌面** 的設計稿。
3. 每一個必要狀態（§6）。
4. 通知權限的 6 種狀態與鎖屏通知範例（§7）。
5. 圖表規格：元素、互動、缺資料的呈現。
6. 元件清單（§9）與各變體。
7. 主畫面 App：圖示（含深色）、啟動畫面、離線與更新提示（§8）。
8. 互動原型：至少涵蓋「總覽 → 個股 → 長按設警報 → 完成」與「通知權限啟用」兩條流程。
9. 說明哪些地方與記帳 App 一致、哪些刻意不同。
